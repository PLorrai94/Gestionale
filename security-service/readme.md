Microservizio Security Service
Questo microservizio gestisce l'autenticazione, l'autorizzazione e la gestione degli utenti e dei ruoli per l'applicazione.

Prerequisiti
Prima di avviare il microservizio, assicurati di avere i seguenti prerequisiti installati e configurati:

Java Development Kit (JDK) 17 o superiore

Maven 3.x

Database Oracle (es. Oracle Express Edition - XE)

Assicurati che sia in esecuzione un Container Database (CDB) con un Pluggable Database (PDB) configurato, ad esempio XEPDB1.

Crea l'utente Flyway (GESTIONALE_OWNER):

SQL

CREATE USER GESTIONALE_OWNER IDENTIFIED BY GESTIONALE_PASS;
GRANT CONNECT, RESOURCE, CREATE VIEW TO GESTIONALE_OWNER;
GRANT UNLIMITED TABLESPACE TO GESTIONALE_OWNER;
ALTER USER GESTIONALE_OWNER QUOTA UNLIMITED ON USERS; -- Assicurati che abbia spazio
Assicurati che GESTIONALE_PASS sia la password esatta configurata in application.yml.

Crea l'utente Applicativo (security_user): Questo utente verrà utilizzato dall'applicazione per le operazioni CRUD dopo le migrazioni di Flyway.

SQL

CREATE USER security_user IDENTIFIED BY SecurityAppPass123!;
GRANT CONNECT TO security_user;
GRANT CREATE SESSION TO security_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON GESTIONALE_OWNER.APP_USER TO security_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON GESTIONALE_OWNER.ROLE TO security_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON GESTIONALE_OWNER.USER_ROLES TO security_user;
-- Grant necessari per le sequenze o le identità auto-generate (se presenti)
GRANT SELECT ON GESTIONALE_OWNER.ISEQ$$_103403 TO security_user; -- Esempio, verifica il nome esatto della sequenza per APP_USER.ID
-- Se necessario, aggiungi altri grant per future tabelle
Adatta SecurityAppPass123! alla password esatta configurata in application.yml e verifica che i nomi delle sequenze (es. ISEQ$$_103403) siano corretti nel tuo database Oracle per le tabelle con GENERATED BY DEFAULT ON NULL AS IDENTITY.

Configurazione
Clona il repository da Git.

Naviga nella directory del microservizio:

Bash

cd security-service
Configura il file src/main/resources/application.yml:

Aggiorna le credenziali del database Oracle nelle sezioni spring.datasource e spring.flyway.

Assicurati che l'URL del database (url) punti correttamente al tuo PDB (es. /XEPDB1).

La sezione spring.flyway userà l'utente GESTIONALE_OWNER per le migrazioni.

La sezione spring.datasource userà l'utente security_user per le operazioni dell'applicazione.

Imposta una secret-key sicura e complessa per JWT in application.security.jwt.secret-key.

Esempio di configurazione DB in application.yml (snippet rilevante):

YAML

spring:
datasource:
url: jdbc:oracle:thin:@localhost:1521/XEPDB1
user: security_user
password: SecurityAppPass123!
# ... altre configurazioni ...
flyway:
enabled: true
url: jdbc:oracle:thin:@localhost:1521/XEPDB1
user: GESTIONALE_OWNER
password: GESTIONALE_PASS
# ... altre configurazioni ...
Avvio del Microservizio
Compila il progetto con Maven:

Bash

mvn clean install
Avvia l'applicazione Spring Boot:

Bash

mvn spring-boot:run
In alternativa, puoi avviare l'applicazione direttamente dalla tua IDE (es. IntelliJ IDEA, Eclipse) eseguendo la classe SecurityServiceApplication.java.

All'avvio, Flyway eseguirà automaticamente le migrazioni del database definite in src/main/resources/db/migration/.

Note aggiuntive
Migrazioni Flyway: Gli script SQL per la creazione dello schema e i dati iniziali si trovano in src/main/resources/db/migration/.

Debug: Per un logging più dettagliato, puoi configurare i livelli di log nel file application.yml (es. logging.level.org.flywaydb: DEBUG).
